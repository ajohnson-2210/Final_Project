# Study scoring method v1.0

The automated scorer is an evidence evaluator, not a second compiler and not an LLM judge. It consumes immutable artefacts generated by the transformation pipeline and applies frozen deterministic rules.

## Core principle

The study asks whether each representation preserves the explicit algorithm semantics supplied by the prior/original representation without inventing missing semantics. General compiler completeness and speculative edge cases are outside the scoring target unless they materially change one of the studied algorithms.

## Scoring scale

- 2: fully satisfied; no material semantic discrepancy detected.
- 1: partial or uncertain; evidence is insufficient for full preservation.
- 0: material discrepancy/stage failure.
- N/A: not legitimately evaluable from available evidence.

Critical semantic criteria with score 0 mark a semantic failure for that stage.

## Separation of evidence and judgement

The transformation pipeline emits evidence such as processing transformations, parser/static-semantic status, AST adjacency, structured flow representation, graph edges, compilation status, and test results. The scoring engine applies its own rule IDs to that evidence. It does not simply trust a transformation's `semantic_change:false` marker in isolation.

Automated results are provisional until human review. Both automated and human assessments are retained, and an adjudicated score is used for final analysis where a reviewer has completed the questionnaire.

## Flowchart metric

`flowchart_delta = flow-stage percentage - AST-stage percentage` is emitted as a stage-fidelity indicator. It is useful for describing whether fidelity improves, remains stable, or degrades across introduction of the flow representation. It is not by itself a causal estimate that flowcharts are superior to pseudocode; a direct-vs-flowchart experimental path would be required for that stronger claim.

## Baseline benchmark

Reference Python acts as the behavioural oracle only when the same defined test inputs are available. Exact source equality and normalised Python-AST equality are recorded descriptively but are not scored as correctness.
