# NL-FDEP v4.19 study folder layout

## Baseline benchmark folder

```text
Baselines/
├── Pseudocode/
│   └── Algorithm - n/
│       ├── Algorithm n Pseudocode.txt
│       └── pipeline_artifacts/          # generated by NL-FDEP
└── Python/
    └── Algorithm - n/
        ├── Algorithm n Baseline Python code.txt
        # or Algorithm n Baseline Python code.py
        └── Algorithm n Tests.json
```

For each Algorithm `n`, reference Python discovery accepts these explicit names:

1. `Algorithm n Baseline Python code.py`
2. `Algorithm n Baseline Python code.txt`
3. legacy `Algorithm n Python.py`

If more than one of those explicitly recognised files exists, the reference is reported as ambiguous rather than guessed. If none exists, the legacy fallback of exactly one `.py` file in the corresponding reference folder remains available.

A `.txt` reference is treated as Python source for validation and behavioural comparison; the source file is not renamed or rewritten.

`Algorithm n Tests.json` discovery is independent. A found reference with no tests therefore produces `TESTS_MISSING`, not `REFERENCE_PYTHON_MISSING_OR_AMBIGUOUS`. Full behavioural calibration still requires suitable test specifications with independently specified expectations where reference validation is required.
