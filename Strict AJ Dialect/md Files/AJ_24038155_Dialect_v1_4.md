# Cambridge-Style Pseudocode — AJ_24038155 Dialect v1.4

## Status

This document defines the **v1.4 delta** from the frozen AJ_24038155 Dialect v1.3 specification. All v1.0, v1.1, v1.2 and v1.3 lexical, syntactic and semantic rules remain normative unless explicitly changed below.

v1.4 adds one narrow language capability required by the frozen baseline corpus: explicit runtime type inspection corresponding to Python `isinstance(...)`.

The addition does not make type names ordinary first-class values and does not add implicit coercion, callbacks, anonymous functions, function references, or general reflection.

## 1. Runtime type inspection

### 1.1 Canonical syntax

A single target type is written as:

```text
CALL ISINSTANCE(value, STRING)
```

Multiple acceptable types are written as a parenthesised type list:

```text
CALL ISINSTANCE(value, (INTEGER, FLOAT))
```

The expression evaluates to an AJ `BOOLEAN`.

### 1.2 Grammar extension

```text
isinstance_expression ::=
    "CALL" , "ISINSTANCE" , "(" , expression , "," , type_reference , ")" ;

type_reference ::=
    runtime_type
  | "(" , runtime_type , { "," , runtime_type } , ")" ;

runtime_type ::=
    "INTEGER"
  | "FLOAT"
  | "STRING"
  | "BOOLEAN"
  | "LIST"
  | "DICTIONARY"
  | "SET"
  | "TUPLE"
  | identifier ;
```

`isinstance_expression` is added to `primary_expression`. The type-reference operand is syntax, not an ordinary value expression.

### 1.3 Semantics

`CALL ISINSTANCE(value, type_reference)` evaluates `value` once and returns `BOOLEAN(TRUE)` when the runtime value is an instance of any supplied target type and `BOOLEAN(FALSE)` otherwise.

For the built-in targets, v1.4 deliberately uses Python-compatible `isinstance` semantics because generated Python is the executable target used by the study. In particular, Python's normal subtype relationships are preserved.

No type test is inserted implicitly. Runtime type inspection occurs only where the source explicitly contains `CALL ISINSTANCE(...)`.

### 1.4 Python translation

```text
CALL ISINSTANCE(value, INTEGER)
-> isinstance(value, int)

CALL ISINSTANCE(value, STRING)
-> isinstance(value, str)

CALL ISINSTANCE(value, (INTEGER, FLOAT))
-> isinstance(value, (int, float))
```

The standard mappings are:

```text
INTEGER    -> int
FLOAT      -> float
STRING     -> str
BOOLEAN    -> bool
LIST       -> list
DICTIONARY -> dict
SET        -> set
TUPLE      -> tuple
```

An identifier used as a runtime type reference denotes a supplied class/type name and is emitted by name.

### 1.5 AST and flow representation

Runtime type inspection is represented by a dedicated `IsInstanceNode` containing:

- the value expression; and
- the ordered list of target type names.

The node evaluates as a Boolean expression and is preserved explicitly in the structured flow representation and human-readable decision labels. It is not collapsed into an ordinary undefined `CallNode`.

## 2. Canonical baseline use

A Python condition such as:

```python
isinstance(var1, (int, float)) and isinstance(var2, (int, float))
```

is represented canonically as:

```text
CALL ISINSTANCE(var1, (INTEGER, FLOAT)) AND CALL ISINSTANCE(var2, (INTEGER, FLOAT))
```

and:

```python
isinstance(var1, str) and isinstance(var2, str)
```

is represented as:

```text
CALL ISINSTANCE(var1, STRING) AND CALL ISINSTANCE(var2, STRING)
```

## 3. Reserved identifier interaction

`ISINSTANCE` is a reserved AJ keyword in v1.4. The existing source-proven reserved-identifier escape rule remains applicable when source binding syntax unambiguously proves that the spelling is instead being used as an identifier.

## 4. Backwards compatibility

All canonical AJ v1.3 programs remain valid under v1.4.

The v1.3 explicit casts and `QUIT` statement are unchanged. `CALL ISINSTANCE(...)` is runtime inspection only; it performs no conversion and must not be substituted for `CALL INTEGER`, `CALL FLOAT`, or `CALL STRING`.

## 5. Versioning

This language revision is recorded as:

**AJ_24038155 Dialect v1.4**

Any later syntax addition, removal or semantic alteration requires a new dialect version.
