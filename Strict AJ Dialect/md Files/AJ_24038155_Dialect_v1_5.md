# Cambridge-Style Pseudocode - AJ_24038155 Dialect v1.5

## Status

This document defines the **v1.5 delta** from the frozen AJ_24038155 Dialect v1.4 specification. All v1.0, v1.1, v1.2, v1.3 and v1.4 lexical, syntactic and semantic rules remain normative unless explicitly changed below.

v1.5 adds two narrow, explicit capabilities required to represent source-supplied Python standard-library dependencies without treating arbitrary comments as executable code:

- exact `COMMENT import ...` / `COMMENT from ... import ...` import directives; and
- the standard-library adapter identifier `string_method_punctuation`, defined as Python `string.punctuation`.

The change does not make arbitrary comments executable, does not infer imports, does not enable dynamic imports, and does not make undefined adapter spellings automatically meaningful.

## 1. Executable import directives

### 1.1 Canonical syntax

The following exact COMMENT payload forms are executable import directives:

```text
COMMENT import <module>
COMMENT import <module> AS <alias>
COMMENT from <module> import <name>
COMMENT from <module> import <name1>, <name2>, ...
COMMENT from <module> import *
```

Examples:

```text
COMMENT import string
COMMENT import numpy AS np
COMMENT from math import sqrt
COMMENT from math import sqrt, floor
COMMENT from math import *
```

The canonical order for wildcard imports is `from <module> import *`. The reversed form `from * import <module>` is not part of AJ v1.5.

### 1.2 Grammar extension

```text
comment ::=
    ordinary_comment
  | import_directive ;

ordinary_comment ::=
    "COMMENT" , comment_text , newline ;

import_directive ::=
    "COMMENT" , "import" , module_reference , [ "AS" , identifier ] , newline
  | "COMMENT" , "from" , module_reference , "import" , import_target_list , newline ;

module_reference ::=
    identifier , { "." , identifier } ;

import_target_list ::=
    "*"
  | identifier , { "," , identifier } ;
```

Import-directive recognition is exact and case-insensitive for the directive keywords. Module, alias and imported-name spellings retain their source identifier spelling.

### 1.3 Semantics

An exact import directive is executable program metadata. It makes the declared Python module or imported name available from the point at which the directive occurs, using ordinary Python import semantics in the generated executable target.

An ordinary `COMMENT` that does not exactly match one of the import-directive forms remains non-executable comment text.

The compiler must not:

- turn arbitrary COMMENT text into Python;
- infer an import that is absent from the source;
- rewrite `COMMENT from * import module` as a valid directive;
- interpret prose containing the word `import` as executable code; or
- silently add imported names not declared by the directive.

### 1.4 Python translation

```text
COMMENT import string
-> import string

COMMENT import numpy AS np
-> import numpy as np

COMMENT from math import sqrt
-> from math import sqrt

COMMENT from math import sqrt, floor
-> from math import sqrt, floor

COMMENT from math import *
-> from math import *
```

The import is emitted at the corresponding lexical location and indentation level. `COMMENT from <module> import *` is restricted to program/module scope because Python does not permit wildcard imports inside function or class bodies.

### 1.5 AST and flow representation

An executable import directive is represented by a dedicated `ImportDirectiveNode` rather than an ordinary `CommentNode`.

The node records:

- directive type (`IMPORT` or `FROM_IMPORT`);
- module reference;
- optional module alias; and
- ordered imported names, including `*` where explicitly supplied.

The structured flow representation preserves the directive as an `IMPORT` operation. Ordinary comments remain `CommentNode` / `COMMENT` metadata.

## 2. Standard-library punctuation adapter

### 2.1 Canonical identifier

AJ v1.5 defines the exact identifier:

```text
string_method_punctuation
```

as the punctuation-character collection exposed by Python's standard `string` module.

### 2.2 Python translation

```text
string_method_punctuation
-> string.punctuation
```

The source remains responsible for declaring the module dependency explicitly when required:

```text
COMMENT import string
```

For example:

```text
COMMENT import string

IF char NOT IN string_method_punctuation THEN
    APPEND char TO filtered_chars
ENDIF
```

lowers to:

```python
import string

if char not in string.punctuation:
    filtered_chars.append(char)
```

### 2.3 Scope of the adapter

Only the exact case-sensitive AJ identifier `string_method_punctuation` receives this mapping.

AJ v1.5 does not infer punctuation semantics for prose such as `is punctuation`, `punctuation`, `ispunct`, or any other undefined predicate or identifier.

## 3. Static semantic interaction

`COMMENT import module` binds the imported module name for subsequent direct identifier reads. When `AS alias` is present, the alias is the bound name.

`COMMENT from module import name1, name2` binds the explicitly listed names.

A wildcard import cannot be statically enumerated by the AJ validator. Routine-call names remain governed by the existing call-resolution policy; v1.5 does not invent a static list of names for `import *`.

The `string_method_punctuation` adapter is source syntax with deterministic lowering. It is not treated as an undeclared variable when used inside expressions supported by the existing Strict grammar.

## 4. Backwards compatibility

All canonical AJ v1.4 programs remain valid under v1.5.

Existing ordinary comments remain non-executable unless their complete payload exactly matches a v1.5 import-directive form.

The v1.4 `CALL ISINSTANCE(...)` rules, v1.3 explicit casts and `QUIT`, and all earlier collection, class, dictionary, function and control-flow semantics are unchanged.

## 5. Versioning

This language revision is recorded as:

**AJ_24038155 Dialect v1.5**
